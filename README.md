# 区域急救药品库存与调拨分析（演示系统）

一个**纯前端**的区域急救药品库存与调拨分析工作台。所有库存推演、调拨候选生成、审批/签收状态迁移均在
**浏览器本地**执行，使用固定演示数据与本地事件适配器，**不连接任何真实医疗系统**，也不做临床替代推断。

技术栈：React 18 + TypeScript（严格模式）+ Zustand 4 + Vite 5；测试：Vitest；部署：Nginx 静态托管 + Docker Compose。

---

## 1. 本地启动

### 方式 A：Docker Compose 一键启动（推荐）

```bash
docker compose up -d --build
# 打开 http://localhost:8080
```

停止：`docker compose down`。

### 方式 B：Node 本地开发

运行时要求 Node 22（仓库在 Node 22.14 / npm 10.9 下验证）。

```bash
npm install            # 如遇 npm 缓存权限问题，可加 --cache ./.npm-cache

```

### 页面手工验证路径

1. 用 `planner / demo1234` 登录，默认分析起日 `2026-11-15`、保障天数 30、参与点位为中心仓与 A/B/C。
2. **缺口分析（双情景）**：查看「保障缺口总览」，表内同时给出未调拨基线与含草稿两列；点击任意缺口行展开，
   可看到双情景 SVG 折线图与逐批次按日明细（日初可用、预计消耗、失效移除、到货、调出、收盘）。
3. **调拨候选**：查看可行候选与「不可行缺口记录」中的保留原因；将候选逐项「加入草稿」，回到缺口分析页确认两情景数字同步变化。
4. **调拨工作台**：勾选草稿 → 整组确认（批准未出库）→ 出库（占用转在途）→ 逐批签收（实收/破损/待查）；
   尝试超额签收会被整组退回；对已出库单点「尝试取消」会被拒绝，改用「登记回程」，回程到货签收后来源库存才恢复。
5. **库存与换算**：查看正式余量、批准占用、在途未来到货三列分离，以及底部「缺换算资料」专区（碘伏条目不参与推演）。
6. **盘点**：在工作台对任一点位做盘点修订，观察未确认草稿变为「盘点后失效」、已批准/在途单据变为「待复核」且数量不被静默修改。
7. 退出后改用 `viewer / view1234` 登录，验证所有写操作按钮禁用或被提示拦截。

## 3. 样例必须实际推演的三个场景

| 场景 | 数据设计 | 实际推演结论（由引擎计算，非文案描述） |
| --- | --- | --- |
| A. 有货但来不及 | 远端点 B 肾上腺素期初 24 支、日耗 8 支；中心仓路线 6 天 | 首缺口日 **2026-11-18**；中心仓 11-15 出库最早 11-21 到货，候选被拒并记入不可行清单「有货但来不及」 |
| B. 到货后先过期 | 供应商批次 40 支 11-22 到 B、11-25 到期 | 22–24 日 FEFO 消耗 24 支，**11-25 余量 16 支全部过期**，之后不再产生满足量；中心仓近效期批次 B-EPI-02 因不满足接收点最低剩余效期（30 天）不能入选 |
| C. 同一批次争用 | 中心仓硝酸甘油仅 100 片，A、C 同为 11-17 缺口 | 按声明优先级 A（2）先于 C（3）逐次分配，同批次累计分配 ≤ 100 片，不超发、不二次许诺；C 的余量改由 A 站库存支援 |

另有预置单据：T-1001 在途、T-1002 批准未出库（占用 20 支）、T-1003 部分签收（4 收/1 损/2 待查/3 在途），
以及需求资料缺失的野外驻点 D（不产生缺口分析、不能被当作富余来源）。

## 4. 核心业务规则落地位置

| 规则 | 实现位置 |
| --- | --- |
| 包装换算只认显式关系，缺资料分开显示、不推断 | `src/domain/units.ts`、`src/data/sampleData.ts`、`InventoryPanel.tsx` |
| 按日推进：失效移除 → 调出 → 到货 → FEFO 消耗，满足/缺货/过期分账 | `src/domain/simulate.ts` |
| 批准未出库占用来源、在途占用未来接收库存，不当自由余量 | `src/domain/projection.ts`、`src/adapters/localEventAdapter.ts` |
| 来源保留量按同范围已声明需求计算；缺需求资料不能当富余仓 | `src/domain/candidates.ts` |
| 到货时未失效且满足最低剩余效期才可候选（出库有效 ≠ 到货可用） | `src/domain/candidates.ts` |
| 按优先级+缺口日逐次分配、扣真实余量、同批不二次许诺、未来足够不重复分配 | `src/domain/candidates.ts` |
| 送出后来源新增缺口必须展示；先比报废再比运输成本，只报可行不宣称最优 | `src/domain/candidates.ts`、`CandidatePanel.tsx` |
| 确认整组预检、部分失败整组退回；试算不写正式库存 | `localEventAdapter.ts`（`transfer.confirmed`）、`useStore.ts` |
| 出库占用转在途不二次扣余额；签收逐批、三量之和守恒、少到停待查 | `localEventAdapter.ts`（shipped/received）、`ReceiveModal.tsx` |
| 取消只释放未发；已发退回程到货恢复；重复/乱序事件幂等 | `localEventAdapter.ts`、`EventLog.tsx` |
| 盘点使草稿失效、已批准安排待复核、不静默改数量 | `localEventAdapter.ts`（stocktake）、`StocktakeModal.tsx` |

## 5. 目录结构

```
src/
├── adapters/      本地事件适配器（纯函数状态机 + 幂等/回滚）
├── components/    React 页面组件（含自研 SVG 双情景图表）
├── data/          固定演示数据（药品/规格/批次/消耗/事件/运输时间）
├── domain/        纯计算引擎：日期、单位换算、按日推演、投影装配、候选生成
├── store/         Zustand store 与 memo 选择器
├── App.tsx        标签页骨架
└── main.tsx       入口
```

## 6. 边界与声明

- 本系统为隔离演示环境：数据为静态虚构数据，事件由本地适配器模拟，无任何网络请求或后端服务。
- 系统只做库存与物流维度的数量推演，**不提供临床用药建议、不做药品替代推断**。
- 候选为基于声明规则的**可行建议**，界面与文档均不宣称全局最优；最终调拨须由保障人员确认。
